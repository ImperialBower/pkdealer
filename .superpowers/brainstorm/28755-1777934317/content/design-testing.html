Design: Testing Strategy

Section 5 of 5 — How to test shared vs. per-game code

Three testing layers

Layer 1 — cardgame_core unit tests

Test the shared infrastructure using a MockGame — a minimal CardGame impl built into the test module that returns scripted responses.

  • Auth: token issuance, seat lookup, rejection of bad tokens
  • Seating: auto-seat, seat-at, remove, double-seat rejection
  • Event broadcast: subscriber receives events, visibility filtering
  • CardVisibility: Hidden / Player / Spectator card redaction
  • Locking: concurrent action requests don't corrupt state
struct MockGame { /* scripted responses */ }
impl CardGame for MockGame { … }
// Tests never touch pkcore
Layer 2 — per-game adapter unit tests

Each *_service crate tests only the thin adapter logic — action parsing and state mapping — not the game engine itself (that's the engine crate's job).

  • Proto → G::Action parsing (valid + invalid inputs)
  • ActionOutcome → proto response mapping
  • Game-specific RPC logic (e.g. GetDummyHand visibility)
  • Error mapping: engine errors → gRPC status codes
// blackjack_service tests
assert!(parse_bj_action("HIT").is_ok());
assert!(parse_bj_action("FOLD").is_err());
Layer 3 — per-game e2e integration tests

Full gRPC round-trip tests that spin up the real service binary in-process (same pattern as existing e2e_two_players.rs) and play a complete game.

  • Seat 2 players, play a full round, verify result
  • Auth rejection on bad token
  • Stream events and verify sequence
  • Game-specific: Blackjack bust, Go Fish book completion, Bridge trick counting
// Same pattern as pkdealer today
// tests/e2e_blackjack.rs
// tests/e2e_gofish.rs

MockGame — the key enabler for Layer 1

By testing cardgame_core against a MockGame rather than a real engine, the shared layer's tests are fast (no game logic), deterministic (scripted responses), and independent of any engine crate. This also serves as a living example of the minimal CardGame implementation a new game needs.

Doc tests (per CLAUDE.md)

Every public method on CardGame, GameServer, RoundResult, and ActionOutcome requires a doc test. The MockGame helper is re-exported under cardgame_core::testing so doc tests in the shared crate can use it without pulling in any game engine.

Test commands (consistent with existing Makefile)

cargo test -p cardgame_core # shared layer + MockGame
cargo test -p blackjack_service # adapter unit tests
cargo test -p blackjack_service --test e2e_blackjack # e2e
cargo test --doc -p cardgame_core # doc tests
cargo test # everything
