Design: GameServer<G: CardGame>

Section 3 of 5 — The generic gRPC server in cardgame_core

Struct definition

// In cardgame_core — written once, used by every game service
pub struct GameServer<G: CardGame> {
  state: Arc<Mutex<GameState<G>>>,
  event_tx: broadcast::Sender<TableEvent>,
  spectator_token: String,
}

struct GameState<G: CardGame> {
  game: G, // the actual engine adapter
  token_to_seat: HashMap<Uuid, u8>,
  seat_to_token: HashMap<u8, Uuid>,
  seat_to_name: HashMap<u8, String>,
}

Base gRPC RPCs — implemented once for all games

Shared (in GameServer impl)
  • ping
  • seat_player
  • seat_player_at
  • remove_player
  • get_status → calls G::player_cards, G::chips, G::phase_name
  • get_chips → calls G::chips
  • get_pot → calls G::pot
  • get_event_log → calls G::event_log
  • get_table_config
  • stream_events
Per-game (in each *_service binary)
  • start_round → calls G::start_round
  • act → calls G::apply_action with game-specific action type
  • get_board → calls G::shared_cards
  • get_next_to_act → calls G::next_to_act, G::valid_actions
  • game-specific RPCs (e.g. Bridge: get_dummy_hand, get_contract)

Data flow: a player action request

Client sends ActRequest (game-specific proto)
  ↓
*_service: extract seat from token (shared helper in GameServer)
  ↓
*_service: parse ActRequest → G::Action (game-specific)
  ↓
GameServer: lock state, call game.apply_action(seat, action)
  ↓
GameServer: emit TableEvent on broadcast channel
  ↓
*_service: map ActionOutcome → game-specific ActResponse proto
  ↓
Client receives response

Per-game main.rs — what ~20 lines looks like

// blackjack_service/src/main.rs
use cardgame_core::GameServer;
use bjcore::BlackjackGame;
use blackjack_proto::BlackjackServiceServer;

struct BjService(GameServer<BlackjackGame>);

#[tonic::async_trait]
impl BlackjackServiceTrait for BjService {
  async fn act(&self, req: Request<ActRequest>)
    -> Result<Response<ActResponse>> {
    let action = parse_bj_action(&req)?; // Hit/Stand/Double
    let outcome = self.0.do_act(req, action).await?;
    Ok(Response::new(outcome.into()))
  }
  // … start_round, get_dealer_hand, etc.
}

#[tokio::main]
async fn main() {
  GameServer::<BlackjackGame>::run(BjService::new()).await
}

Key insight: shared helper methods on GameServer

Rather than exposing raw state, GameServer<G> exposes helper methods that per-game services call: do_act(), do_seat_player(), token_to_seat(), emit_event(). This means auth + locking + broadcasting logic is never duplicated across games.
